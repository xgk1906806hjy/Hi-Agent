# config — 功能逻辑

## 1. 职责

从**多层 .env** 与进程环境变量加载 OpenAI 兼容接口配置，并记录启动时的工作目录。  
工具读写、会话落盘均相对进程 cwd，因此可在任意项目路径下启动同一份 `hi-agent` 二进制。

## 2. 代码位置

| 文件 | 说明 |
|------|------|
| `internal/config/config.go` | `Config`、`Load`、分层 dotenv |
| `internal/config/config_test.go` | 路径链与环境快照还原 |
| `internal/config/setup_env.go` | `ApplyEnvFile`：解析 .env → 写全局 |
| `internal/config/setup_env_windows.go` | Windows 用户环境变量（PowerShell） |
| `internal/config/setup_env_unix.go` | Unix：`env.sh` + shell rc 挂载 |
| `scripts/setup-env.{ps1,cmd,sh}` | 跨平台一键脚本入口 |

## 3. 数据结构

```go
type Config struct {
    BaseURL  string
    APIKey   string
    Model    string
    WorkDir  string   // 绝对工作目录
    EnvFiles []string // 实际加载的 .env（低→高优先级）
}
```

## 4. 环境变量

| 变量 | 是否必填 | 默认值 | 说明 |
|------|----------|--------|------|
| `OPENAI_API_KEY` | **是** | — | 为空则退出 |
| `OPENAI_BASE_URL` | 否 | `https://api.deepseek.com` | |
| `OPENAI_MODEL` | 否 | `deepseek-v4-flash` | |

`GEEKAGENT_*` 亦参与「进程环境快照还原」，避免被 dotenv Overload 盖掉 shell 里已 export 的值。

## 5. `.env` 加载优先级（高 → 低）

1. **进程环境变量**（启动前已 export / 系统设置）  
2. **工作目录向上**路径上的 `.env`（越靠近 cwd 越高；会对较低层 Overload）  
3. **用户全局** `~/.hi-agent/.env`（Windows：`%USERPROFILE%\.hi-agent\.env`）

实现：先 Overload 全局与祖先→cwd 的 `.env`，再把启动前快照的键强制写回。

## 6. `setup-env`（一键配置）

入口：`hi-agent setup-env [path]` 或 `scripts/setup-env.*`。

1. 解析源 `.env`（`KEY=VALUE`，支持 `#` 注释与可选引号 / `export`）。  
2. 原样复制到 `GlobalEnvPath()`（`~/.hi-agent/.env`）。  
3. 将非空的 `OPENAI_API_KEY` / `OPENAI_BASE_URL` / `OPENAI_MODEL` 写入用户级环境：  
   - **Windows**：写入 `HKCU\Environment` 注册表，并 `Setenv` 当前进程。  
   - **Unix**：写 `~/.hi-agent/env.sh`，在 `.profile` / `.bashrc` / `.zshrc` 插入可替换标记块。  
4. 提示重开终端（或 `source`）；**不**改已打开的无关进程环境。

## 7. 边界

- 不验证 URL / 密钥有效性。  
- 会话与 `.geekagent/` 仍落在 **cwd**，不写到全局目录。  
- `setup-env` 只持久化上述三个 OPENAI_* 键到系统环境；其它键仅留在全局 `.env` 文件中。
