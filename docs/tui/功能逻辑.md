# tui — 功能逻辑

## 1. 职责

轻量全屏终端界面：左侧消息区、右侧状态面板、底部输入行。  
输入仍走 cooked mode（`bufio.Reader` 读行）；渲染用 ANSI 绝对定位整屏重绘。

## 2. 代码位置

| 文件 | 说明 |
|------|------|
| `tui.go` | `TUI` 生命周期、消息追加、节流重绘、读行与确认 |
| `panel.go` | 右侧面板文案与进度条 |
| `layout.go` | 显示宽度、折行、截断（CJK 按 2 列） |
| `vt_windows.go` / `vt_other.go` | Windows 启用 VT 处理 |

## 3. 布局

```
┌─────────────────────────────┬────────────────┐
│ 消息区（可滚动尾部）         │ 右侧面板       │
│                             │ 模型/会话/状态 │
│                             │ 上下文进度条   │
│                             │ 本轮/累计 tokens│
├─────────────────────────────┴────────────────┤
│ 分隔提示行                                   │
│ You › 输入…                                  │
└──────────────────────────────────────────────┘
```

- 终端宽 ≥ 80：右侧固定 34 列；否则隐藏面板，消息区占满。  
- 可视行 = 终端高 − 2（提示行 + 输入行）。

## 4. 生命周期

1. `Supported()`：stdin 与 stdout 均为 TTY。  
2. `Start()`：启用 VT → 进入备用屏幕 `\x1b[?1049h` → 清屏 → 首次 `Flush`。  
3. 运行中：`Model`/`Progress`/`Info` 等修改 entries → `Refresh`（节流 40ms）或 `Flush`。  
4. `Close()`：复位颜色、显示光标、退出备用屏幕、恢复 ConsoleMode（可重复调用）。

## 5. 消息写入

| 方法 | 行为 |
|------|------|
| `UserEcho` | 追加用户行（先关开流段落） |
| `Model` | 追加/合并流式模型正文 |
| `Progress` | 工具进度；过长截断展示 |
| `Info` / `Notice` / `Error` | 系统 / 提示 / 错误 |
| `BeginReply` / `EndReply` | 面板「生成中」状态 |

## 6. 面板数据

由调用方 `panel func() Panel` 每帧提供：模型、会话、上下文 tokens、历史字符、本轮/累计用量、工具轮次。  
`Busy` 由 TUI 自身根据 Begin/End 覆盖。

## 7. 边界

- 不用 bubbletea / tview 等框架。  
- 确认 diff 写入消息区后再在输入行问 y/N（与 Day3 语义一致）。  
- 窄终端自动隐藏右栏。  
- 非 TTY 或 `GEEKAGENT_TUI=0` 时 REPL 不创建本模块。
