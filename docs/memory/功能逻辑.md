# memory — 功能逻辑

## 1. 职责

保存当前项目的长期记忆（Day 10），并提供两种读取方式：

- 显式搜索：`memory_search` / `Search` 的子串匹配；
- 主动召回（Day 13）：每轮用户输入自动用 BM25 取最相关的 Top5 记忆块，交给 `chat` 临时注入 system。

换会话仍能搜到；换项目则换成新目录下的文件。

代码：`internal/memory/memory.go`。不依赖 `tools` / `chat`；主动召回由 REPL 通过 `chat.SetRecall(memory.RecallNote)` 注入。

## 2. 文件

工作区 `.geekagent/memory.json`，JSON 数组：

```json
[{ "id": "a1b2c3d4", "content": "喜欢用 Go", "createdAt": "2026-10-13T21:00:00+08:00" }]
```

`id` 为 8 位 hex。只追加，不修改、不删除。

## 3. API

| 函数 | 说明 |
|------|------|
| `Write(content)` | 追加一条并落盘 |
| `Search(query)` | 不区分大小写的子串匹配，最多 5 条（显式 `memory_search` 使用） |
| `Recall(query, topN)` | 切块 + BM25，返回得分最高的 `topN` 个 `Hit`；`topN<=0` 时取 5 |
| `RecallNote(query)` | 把召回结果拼成可直接放进 system 的文本；没有命中/读取失败返回空串 |
| `List()` / `Lines()` | 全部记忆；`Lines` 供 `/memory` |

`Hit` 字段：`EntryID`、`Content`（记忆块）、`Score`。

工具 `memory_write`、`memory_search` 在 `internal/tools` 注册，默认 allow。

## 4. 主动召回（Day 13）

1. **切块**：先按空行分段，再按中英文句末标点（`。！？!?；;`）切句并聚合；单块最多 **240 rune**。单句超长时硬切。
2. **分词**：拉丁字母/数字按连续词并转小写；CJK 文档侧生成单字 + 双字 gram，查询侧主要用双字 gram（单字查询才保留单字），以降低「我」「的」等高频单字带来的噪声。
3. **BM25**：`k1=1.2`、`b=0.75`；查询词对应的 IDF 加权，块长度归一化。
4. **过滤与排序**：只保留至少命中一个查询词项的块；按分数降序，同分优先较新的记忆，最多 5 块。
5. **注入**：`RecallNote` 生成「项目长期记忆·自动召回」说明；`chat` 把它作为本轮临时 system，不写入 history。

每次调用都按当前工作目录读取并计算，不维护持久化索引。

## 5. 边界

- 不做 embedding / 向量库，也不建持久化 BM25 索引。
- 不做记忆的修改和删除。
- 文件损坏时 `Write` / `Search` / `List` / `Recall` 返回错误，不悄悄清空；`RecallNote` 为不阻断对话会吞掉读取错误并返回空串，`/memory` 仍会报告错误。
- 跟随进程工作目录。`/project` 切目录后，下一轮读写的就是新项目的文件。
