# skills — 功能逻辑

## 1. 职责

扫描工作区 `skills/*/SKILL.md`，把用户选中的技能转成：

- 一段附在请求最前的 **system 指令**；
- 一份 **工具白名单**（技能声明了 `tools` 时）。

技能不注册新工具、不改权限策略，只影响模型「看到什么、被告知怎么做」。代码：`internal/skills/`。

## 2. 目录与文件格式

```
skills/
└── code-review/
    └── SKILL.md
```

`SKILL.md` 可选 YAML 风格 frontmatter，正文即指令：

```markdown
---
name: code-review
description: 只读审查改动
tools: read, glob
---

审查步骤……
```

| 字段 | 说明 |
|------|------|
| `name` | 展示名，默认取目录名 |
| `description` | 一句话说明，拼进 system 与 `/skills` |
| `tools` | 工具白名单；支持 `read, glob`、`[read, glob]`、多行 `- read` 三种写法；留空表示不限制 |

- 正文按 **8000 字**截断，避免 system 无限膨胀。
- 同名技能只保留按目录名排序先扫描到的那个。
- 目录不存在视为「没有技能」，不报错。

## 3. API

| 函数 | 说明 |
|------|------|
| `Scan()` | 读取 `skills/` 下全部技能，按名称排序 |
| `Find(list, name)` | 按名称查找（忽略大小写） |
| `Names(list)` | 技能名列表 |
| `Note(active)` | 拼 system 正文；没有技能返回空串 |
| `Tools(active)` | 工具白名单并集；都没有声明时返回 `nil`（不限制） |

## 4. 加载与生效流程

```mermaid
flowchart TD
  A["/use 名称"] --> B[重新 Scan]
  B --> C{找到?}
  C -->|否| D[提示未找到]
  C -->|是| E[active[name]=true]
  E --> F[Note + Tools]
  F --> G["chat.SetSkills(note, allow)"]
  G --> H[下一轮请求]
  H --> I["messages 最前附技能 system"]
  H --> J["tools 只导出白名单"]
```

- 技能状态在 **进程内**，重启或换项目后需要重新 `/use`；`/project` 后会按新目录重新扫描，并丢掉新目录中不存在的技能。
- `chat.SetSkills` 只改请求，不写入 `history`，因此不进入会话落盘。
- `delegate_task` 的子对话继承主对话的技能片段与白名单。

## 5. 命令

| 命令 | 行为 |
|------|------|
| `/skills` | 重新扫描并列出（`*` 为已加载），显示描述与声明的工具 |
| `/use <名称>` | 加载并立即生效；无参数等价 `/skills` |
| `/unuse [名称]` | 卸载指定技能；省略名称卸载全部 |

## 6. 工具白名单规则

1. 所有已加载技能声明的 `tools` 取**并集**；没有任何声明时保持全部工具。
2. 工具轮次后期「只读收缩」仍生效：白名单与 `ReadonlyNames()` 取交集；没有白名单时只留只读。
3. 交集为空表示本轮一个工具都不给（`tools.ToOpenAIAllow` 区分 `nil` 与空切片）。
4. 白名单只是「不给模型看」，不是安全边界；越权调用仍由 `permission` 的 deny/ask 拦截。

## 7. 边界

- 不做 `tools.ts` 动态加载（Go 无运行时插件）；技能只能引用已注册工具。
- 不持久化加载状态，不按会话区分。
- 不校验 `tools` 中的名字是否存在；不存在的名字被忽略（不会出现在 tools 参数里）。
- 技能正文直接进 system，视为用户可信输入；不要加载来源不明的技能。

## 8. 示例

仓库 `skills/code-review/`、`skills/explore/` 为只读示例：分别用于代码审查与代码库探索。
