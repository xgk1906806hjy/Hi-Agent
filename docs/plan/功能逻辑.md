# plan — 功能逻辑

## 1. 职责

保存当前进程的任务清单（Day 9），供 `todo_write` 写入、TUI 右栏与 GUI 侧栏只读展示。

代码：`internal/plan/plan.go`。不依赖 `tools` / `chat` / 界面。

## 2. 状态

| 状态 | 含义 | 界面标记 |
|------|------|----------|
| `pending` | 未开始 | ○ |
| `in_progress` | 进行中 | ● |
| `completed` | 已完成 | ✓ |
| `cancelled` | 已取消 | – |

同时最多一项 `in_progress`。同一次 `Apply` 里多项设为进行中时，**最后一项保留**，其余降为 `pending`。

## 3. API

| 函数 | 说明 |
|------|------|
| `Apply(updates)` | 按 ID 合并。新任务必须有 content；更新时可只改 status。返回清单文本 |
| `List()` | 副本，供 GUI |
| `Lines()` | `标记 + 内容`，供 TUI |
| `Reset()` | 清空。REPL 在 `/project` 切换后调用 |

## 4. 边界

- 只在内存中，不写入 `.geekagent/`，进程退出即丢。
- 不按会话分隔：同一项目内的对话共用一份清单；换项目清空。
- ID 不能含空白或路径分隔符。
