# plan — 功能逻辑

## 1. 职责

保存当前会话的任务清单（Day 9），供 `todo_write` 写入、TUI 右栏与 GUI 侧栏只读展示。清单按会话落在工作区 `.geekagent/todos.json`。

代码：`internal/plan/plan.go`。不依赖 `tools` / `chat` / 界面。

## 2. 状态

| 状态 | 含义 | 界面标记 |
|------|------|----------|
| `pending` | 未开始 | ○ |
| `in_progress` | 进行中 | ● |
| `completed` | 已完成 | ✓ |
| `cancelled` | 已取消 | – |

同时最多一项 `in_progress`。同一次 `Apply` 里多项设为进行中时，**最后一项保留**，其余降为 `pending`。

## 3. API

| 函数 | 说明 |
|------|------|
| `Apply(updates)` | 按 ID 合并。新任务必须有 content；更新时可只改 status。返回清单文本 |
| `List()` | 副本，供 GUI |
| `Lines()` | `标记 + 内容`，供 TUI |
| `Activate(dir, id)` | 先保存当前会话，再载入目标目录下该会话的清单。首次调用只载入 |
| `Move(dir, old, new)` | 清单键随会话重命名走 |
| `Drop(dir, id)` | 删掉该会话的清单 |
| `Reset()` | 清空内存并解除落盘绑定（测试用） |

## 4. 边界

- 文件结构：`{"sessions": {"会话ID": [{id, content, status}]}}`。
- `todo_write` 成功后立即保存。`/open`、`/new`、`/rename`、`/delete`、`/project` 先保存再载入目标。
- 换项目载入新目录下当前会话的清单，不清空成空白。
- 同时最多一项 `in_progress`。ID 不能含空白或路径分隔符。
