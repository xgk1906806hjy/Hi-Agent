# rag — 功能逻辑

## 1. 职责

项目级轻量 RAG（Day 14）：把工作区内的文档按段落切块，建立可持久化的 BM25 索引；模型通过 `rag_search` 只取回相关片段和来源段号，避免把整篇文档塞进当前上下文。

代码：`internal/rag/`。工具注册与路径检查在 `internal/tools/rag.go`；REPL 提供 `/rag`。

## 2. 索引文件

工作区 `.geekagent/rag/index.json`：

```json
{
  "version": 1,
  "updatedAt": "2026-10-27T10:00:00+08:00",
  "chunks": [
    { "source": "docs/guide.md", "seq": 1, "content": "第一段……" }
  ]
}
```

- `source`：相对当前工作目录的 `/` 分隔路径。
- `seq`：同一来源内的段号，从 1 开始。
- 只保存切块后的文本，不保存整篇原文的额外副本。
- 同一文件/目录再次 `rag_add` 时按范围重建旧块；不会产生重复段。

## 3. API

| 函数 | 说明 |
|------|------|
| `Path()` | 返回索引相对路径 |
| `Add(path)` | 读取文件或目录，切块并写入索引；返回来源统计，不返回全文 |
| `Search(query, topK)` | BM25 检索，返回 `Hit{Source, Seq, Content, Score}`；`topK<=0` 时取 5 |
| `Stats()` / `Lines()` | 索引来源数、段数、更新时间；`Lines` 供 `/rag` |
| `Clear()` | 删除索引文件 |

### 3.1 `Add`

1. `path` 可以是文件或目录；目录递归处理。
2. 跳过 `.git`、`.geekagent`、`node_modules`、`dist`、`build`、`.next`、`.venv`、`venv`、`__pycache__`。
3. 目录遍历跳过符号链接；超过 1MB、含 NUL、非 UTF-8 或空文本的文件也跳过；单文件读取失败只计入跳过数。
4. 文件内容按段落/句末标点聚合，单块最多 **800 rune**，超长句硬切。
5. 先按范围删除旧块，再写新块；目录范围会清掉该目录下已不存在的旧来源。
6. 返回 `AddResult{Sources, Chunks, Skipped}`；`Sources` 只含成功索引的来源及段数。

### 3.2 `Search`

1. 读取索引；没有索引返回空结果，不报错。
2. 分词：拉丁字母/数字按连续词并转小写；CJK 文档侧单字 + 双字 gram，查询侧主要用双字 gram（单字查询保留单字）。
3. BM25：`k1=1.2`、`b=0.75`，按来源段号定位。
4. 只保留至少命中一个查询词项的块；按分数降序，同分按来源、段号排序，最多 `topK` 段。

## 4. `/rag`

- `/rag`：列出索引段数、来源数、更新时间与各来源段数。
- `/rag clear`：确认后删除索引文件。
- 索引为空时提示先使用 `rag_add`。

## 5. 工具

- `rag_add`：参数 `path` 必填；工具层先经 PathGuard，再调用 `rag.Add`。默认 allow。
- `rag_search`：参数 `query` 必填、`top_k` 可选（默认 5，范围 1–20）；只返回相关片段，格式 `[source#seq] 内容`。默认 allow，且属于只读工具，工具集收缩时仍可用。

## 6. 边界

- 不做 embedding、向量库、外部检索服务或自动每轮注入。
- 不采集 URL；远程内容先用 `fetch`，再保存为工作区文件后 `rag_add`。
- 不提供单段修改/删除；重新 `rag_add` 同一来源会重建，`/rag clear` 清空全部。
- 索引损坏时读取返回错误，不悄悄清空；`rag_add` 不会覆盖损坏文件。
- 索引跟随进程工作目录；`/project` 切目录后使用新项目的索引。
